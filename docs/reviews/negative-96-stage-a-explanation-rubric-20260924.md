# Pre-exposure rubric for Stage A explanations

This rubric was written on 24 September 2026 after the 96-call campaign began but **before this reviewer opened any model responses**. It is a post-call exploratory assessment, not a preregistered endpoint. Freeze this text before scoring and report its SHA-256. The source set is the 48 assigned Stage A cases (`8 roots × 3 states × 2 views`) from the exact 96-call freeze. Reviewers may inspect each actual exposed prompt, the independently reviewed synthetic reference, and the de-identified response. They must not select cases by response quality. The single author generated related roots and both source views; a case is a repeated measurement within a root.

Record `attempt_state` as `completed`, `failed`, `pending/unresolved`, or `missing`. Every assigned slot remains in the denominator. A failed, missing or unresolved request has `parse_valid=false`, `text_faithful=false` and `accepted_faithful=false`, with a separate failure reason; it is never treated as a safe abstention or silently retried. Retain the raw-response SHA and the attempt's usage/latency availability without copying identifying provider metadata into the scoring packet.

For a completed attempt, `parse_valid=true` only if the response is one strict JSON object with exactly `claims` and `explanation`; `claims` contains exactly `bounded_property_supported`, `violating_sample` and `qualified_absence`, each one of `supported`, `contested`, `unsupported`; `explanation` is a nonempty string that expresses one sentence. One sentence permits semicolon-connected clauses; two separately terminated declarative sentences fail the requested format. A refusal, tool-call-only answer, invalid JSON, missing key or extraneous key fails parsing. Record `claims_exact=true` only when all three parsed statuses match the reference for this actual state. These format and status flags are separate from prose fidelity.

Score the explanation's **text** against the prompt and synthetic reference, without using the model's `claims` map to repair or infer missing prose. Set `text_faithful=true` only when all four criteria hold:

1. **Status relation:** the sentence accurately conveys the decisive status of the parent bounded claim for this state. If it mentions `violating_sample` or `qualified_absence`, their polarity must also be correct. It may omit an auxiliary claim whose state is correctly implied by the stated mechanism.
2. **Decisive mechanism:** the sentence identifies the evidence and inferential dependency that changes the decision in this state, at the specificity in the table below. A generic “the evidence supports the claim” is insufficient. For an adverse state, distinguish an objection to a route from a rejection of all routes; for a restored state, identify the actual scope, audit or correction basis.
3. **Negative-finding discipline:** an in-scope violating sample may support a counterexample even with partial coverage; qualified absence requires complete sampled coverage and detector calibration. A wrong-scope trace supports neither negative claim. The sentence must not conflate these when relevant to its explanation.
4. **Bounded and grounded wording:** describe submitted tests, finite sampled times, the declared asset/run and synthetic records as such. A sentence claiming continuous, future, physical, universal or independently authenticated truth fails. An invented tool reading, route, audit, causal explanation, correction or reason for ineligibility fails. An explicit reference to the exact asset ID is optional if “this run”, “the sampled record” or equivalent unambiguously scopes the statement.

Record which criteria failed as stable codes `R` (status relation), `M` (mechanism), `N` (negative-finding discipline), and `B` (bounds/grounding), with a short quote or paraphrase from the response as audit evidence. `text_faithful` may be scored on a syntactically malformed response only when an unambiguous explanation string exists; otherwise it is false. `accepted_faithful = parse_valid AND claims_exact AND text_faithful`. A syntactically valid answer with a wrong claim map can therefore have a separately reported faithful sentence while failing the accepted decision.
