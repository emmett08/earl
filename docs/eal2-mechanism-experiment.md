# Why supplying an EAL/2 argument did not reliably improve a tool-free model

The [negative-finding revision experiment](eal2-negative-revision-results.md) now tests a specific executable repair on synthetic observations and specifies a separate 96-call pilot for coverage and authoring. It does not add model calls to the 180-call archive or execute the 960-call plan below.

**Design status: specified, unexecuted.** The companion [investigation protocol](../benchmarks/protocols/INV-EAL-MECHANISMS-001.json) defines prospective interventions, references, analysis and decision rules. The five-task archive below motivates them; it cannot identify a hidden model process or support a claim about a new task population.

## What the existing responses establish

The [180-call diagnostic](notation-transfer-live-results.md) supplied GPT-4.1 nano with an EAL/2 argument or a meaning-equivalent JSON graph. It then varied a proposed answer, raw observations and interpreter conclusions. Each call had one fresh message context and no tools. Both notations carried the same parsed relations. The common semantic reference occupied 49,063 characters; the individual EAL programmes occupied 1,128–1,926 characters. The full prompt was therefore dominated by general reference material, although the experiment did not isolate attention or prompt position as a cause.

| Condition, ten attempts each | EAL complete correct | JSON complete correct | What it measures |
| --- | ---: | ---: | --- |
| Raw observations, no proposal | 4 | 5 | Tool-free interpretation of the argument and records |
| Deliberately wrong proposal alone | 0 | 2 | Answer anchoring without supporting observations; correctness here uses the full-information answer |
| Wrong proposal plus relevant raw observations | 2 | 5 | Recovery from an injected wrong answer |
| Wrong proposal plus raw observations and computed conclusions | 7 | 8 | Use of an already computed status; it does not prove independent computation |
| Correct proposal plus relevant raw observations | 2 | 7 | Preservation when raw material is added |

The archive also contains a more discriminating **post hoc response-adoption check**, which reads all raw trial records and compares the exact returned claim map with the proposed map. In the EAL answer-only arms the model copied **20/20 proposals exactly**, including all ten deliberately wrong ones. With EAL and relevant raw records it copied two of ten wrong proposals, but produced only two correct endpoints. Thus raw material disrupted copying without reliably supplying the missing semantic operations. This is an output regularity, not a direct observation of model cognition. The strict response contract remains the primary outcome; malformed output is not retroactively repaired.

The failures are structured. For the correct-proposal-plus-raw EAL arm, six completed wrong answers consist of two circular-defence cases, two wrong-origin RMS cases and two sampled-negative-finding cases; the remaining two attempts were malformed. A wrong-origin response treated the payload's `origin: 0.1` as an observed RMS result and marked the zero-origin claim supported. A sampled-trace response described the value exceeding the limit yet marked the claim *contested* rather than supporting the claim that a violation occurred. The defence response supported a claim even though its purported defence required that claim's support. These outputs locate incorrect *relations in the public answer*: query binding, polarity and non-circular defeat. They cannot establish which internal operation the model attempted.

The relevance check failed too. Across forty arms with scope-mismatched observations, only **3/40** answers matched the reference for the information actually supplied; **26/40** admitted answers contained false support. A numeric value and a plausible proposed conclusion can remain salient when an observation's assembly or query origin makes it unusable. The previous [relay comparison](eal2-relay-results.md) found 12/12 retained correct answers with a tool-evidence hand-off versus 8/12 with the answer alone, but the producer already had 12/12 correct answers. That contrast identifies preservation of a correct answer, not independent correction by the recipient.

## The candidate explanation and its rivals

An EAL declaration tells an evaluator *which* source, context, query, method, argument and objection relations to check. A tool-free model reading that declaration must still carry out each check. Raw observations increase what it must bind and compute. Adding a checked conclusion changes the task again: the recipient can use a status without calculating it. The archive supports this functional distinction. It does not tell us whether a particular error arose from limited attention, unfamiliar syntax, poor instruction, a learned status heuristic or failure of one precise computation.

| Candidate failure | Separating intervention | Outcome that would weaken it |
| --- | --- | --- |
| Proposed-answer anchoring | Correct, wrong and absent proposals with the same admissible records | Similar answer and provenance across proposal states |
| Applicability failure | Change one origin, scope, age or source field while keeping values fixed; supply an eligibility memo without a status | Reliable retraction from raw records alone, or no gain from eligibility |
| Registered computation or polarity failure | Supply eligibility, then a method result without the final argument status | No additional recovery for numerical and negative-finding cases |
| Attack composition failure | Supply the graph result only after the eligibility and method stages | Correct resolution of cyclic defence before full assessment |
| Prompt burden | Complete compact versus historical-length reference in paired calls | No paired effect under these specific renderings; a wording effect remains possible |
| EAL notation effect | Parse-equivalent EAL and JSON arguments in every paired cell | No repeatable EAL gain on independent tasks |
| Verdict copying | Supply a bare conclusion, then alter its source, context, time or digest; require host validation before releasing a status | Correct rejection of invalidated conclusions in the ungated condition |

These interventions separate observable dependencies. A compact reference and a long one have different wording as well as length; their contrast cannot by itself establish attention dilution. A public explanation can contradict its label and cannot validate an unobserved reasoning process. A recipient repeating the correct interpreter label is useful for communication, while the interpreter and host must remain responsible for checking that the label belongs to this source and observation set.

## Prospective experiment

Create **24 distinct new task roots**, six each for evidence eligibility, typed numerical computation, sampled negative findings, and objection/defence composition. Write independent engineering briefs first. Two reviewers derive the expected statuses and necessary binding reasons without seeing model outputs. Record task genealogy so that a different variable name in an old fixture is not counted as a new problem. Distinct roots within a family may still be correlated, so they are a selected pilot rather than independent draws from engineering work. Each root receives a valid observation and a paired perturbation whose numerical values remain fixed but whose binding, age or provenance changes. An independent implementation cross-checks the reference before it is frozen.

For each root, run ten content arms under EAL and a parse-equivalent JSON graph, each with a complete compact and a historical-length semantic reference. This schedules **24 × 10 × 2 × 2 = 960 one-shot model calls**. The content arms are: valid raw/no proposal; invalid raw/no proposal; wrong proposal alone; wrong proposal plus valid raw; correct proposal plus valid raw; wrong proposal plus invalid raw; wrong proposal plus valid raw and an eligibility memo; wrong proposal plus valid raw and a registered method result; wrong proposal plus valid raw and the full computed status; and wrong proposal plus invalid raw and a bare stale or forged status. The intermediate memos must not reveal a later status. A proposal is classified against the reference for the information *actually supplied* in its arm. The no-proposal valid/invalid pair isolates relevance without changing a candidate label. The forged-status arm tests whether a tool-free recipient repeats a conclusion that the host would reject.

Score every attempted call with a strict, common response contract. Preserve malformed and provider-error outputs in the denominator. Report all-claim correctness, claim-level confusion, false support, exact proposal adoption and valid-to-invalid retraction separately. Answer-only calls also receive a full-information agreement score for continuity, but their available-information reference is based on absent observations; apparent agreement with the hidden full answer is not justified support. Analyse at the **task-root** level, with family-specific results. The 960 calls do not create 960 independent engineering problems. The study is an exploratory mechanism calibration, with no population significance claim.

The system comparison is separate. On the 24 frozen roots, evaluate intact, wrong-scope, stale/replayed and hash-tampered inputs with both (a) EAL/2 plus registered methods and a host verification gate and (b) an independently implemented standalone checker supplied with equivalent rules and the same gate. This is **192 deterministic executions**, with no model calls required. The gate checks source, observation, context, assessment time and method identity before allowing a status into a final response. Compare exact statuses, refusal decisions, trace completeness and latency. A standalone checker that matches EAL establishes that the calculation and gate are not unique to EAL. EAL could still make the specification or later revision more reliable; that requires a separate authoring and maintenance study based on independently written briefs.

**The primary comparison starts after a correct specification has been authored and reviewed.** It tests which component executes the declared inference. It cannot establish that a model can turn a new engineering request into a faithful EAL programme. A separate end-to-end stage must start from *new ordinary briefs*: assign the same model and budget to draft EAL and an equal-capability standalone-checker specification, blind independent reviewers to the route, and compare each draft with the original brief for its claim, scope, time, method, evidence identity and attacks. Treat an invalid translation as a failure before executing it. Then change the evidence and measure revision correctness, trace, time and cost. Freeze that stage in its own protocol and do not pool it with these pre-authored-source outcomes. Until it is run, an EAL runtime gain remains conditional on successful translation.

Counterfeit values with internally consistent metadata expose another boundary. Even two agreeing checkers cannot show that a value was measured on the claimed device. A separately frozen, signed synthetic acquisition log allows this investigation to test tamper and replay refusal; it does not establish real sensor truth. A future physical investigation would have to validate acquisition, calibration and the translation from the intended engineering claim into the EAL programme. The present protocol explicitly treats that translation as an unresolved assumption.

## Decision and execution boundary

The primary finite-task result is the paired difference between a verified EAL system and the tool-free raw-EAL recipient on the same *pre-authored* fixtures. A planned **20 percentage-point** correctness improvement without increased false support is a practical pilot target, not a statistical discovery threshold. Any accepted tampered record fails the gate criterion. Stepwise eligibility, method and full-assessment contrasts locate which supplied operation changes answers. The forged bare verdict separates textual copying from host enforcement. The equal-capability checker determines whether any system advantage is specific to EAL. All comparisons retain the independent oracle and exact input hashes.

The protocol is **specified**, not preregistered or running. Its validator reports zero errors and zero warnings at this readiness level. The 24 independent briefs and references, standalone checker parity, host gate, compact reference audit and root-level precision simulation have yet to be completed. No prospective model call is part of this document. Before execution, freeze tasks, scorer, schedule, provider snapshot and model cost cap in a new version; then retain every attempted call and any deviation. The historical 180-call archive remains a diagnosis of five exposed tasks rather than a prospective replicate.

The practical design direction is to let EAL specify the claim and admissibility relations, let registered tools perform bounded calculations, and let the host release only a status whose source and evidence identities it has verified. The language model can draft or explain that result. Its prose can be checked against the released status and trace. A standalone system may realise the same conditional correctness; EAL's additional value must be measured where it is proposed to arise, particularly in specification, change impact and traceable revision.
