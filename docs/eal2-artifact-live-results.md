# EAL/2 artifact recipient pilot: live result

**Execution:** 24 September 2026, PR head `815ae25ee75b8a81ec88a600efcaa35e36cd6f18`. The frozen 48-request schedule completed with `gpt-4.1-nano-2025-04-14` returned by Chat Completions. Four selected synthetic roots each supplied three correlated evidence states to four recipient arms. There was one response per state and arm. The host assessed each state before the recipient call. This is a developmental feasibility measurement, with four independent task roots and no source-authoring or equal-checker comparison.

The first request used the requested alias `gpt-4.1-nano`. The provider returned the dated identity, so the runner retained its response and usage, stopped, and created a **new freeze** pinned to that returned identity. This first billed attempt is outside the 48-case analysis. No attempt was silently retried. The completed ledger contains 48/48 responses, all with a returned model identity and billing usage. The source-tree preflight regenerated byte for byte from the PR head; all 12 brief-level oracle statuses matched the interpreter; the ten offline pilot tests passed.

## Recipient outcomes

The primary outcome requires exactly the named claim in a JSON `claims` object and the correct fixture status. “Named status” is a diagnostic extraction that tolerates additional claim keys; it does not satisfy the required output contract. There are four adverse states per arm: three unsupported and one contested. False support counts only an explicit `supported` status on one of these states.

| Recipient arm | Exact correct / 12 | Valid format / 12 | Named correct / 12 | False support, valid / 4 | False support, named / 4 |
|---|---:|---:|---:|---:|---:|
| Raw EAL | 3 | 8 | 5 | 2 | 3 |
| Derived JSON graph | 8 | 11 | 8 | 3 | 3 |
| EAL with application instruction | 5 | 7 | 7 | 1 | 2 |
| Checked host packet | 10 | 12 | 10 | 0 | 0 |

The JSON graph gained five exact answers over raw EAL on paired states and lost none. These gains occurred across **two of four roots**; the other two roots tied on exact-answer counts. The explicit application instruction gained two paired states and lost none. The packet gained seven and lost none, but its input **contained the host's answer**, so its result measures delivery fidelity rather than independent reasoning. The packet still gave the wrong status on both supported HL-5 complete-inspection states. These are descriptive comparisons on selected fixtures; twelve within-root states are not twelve independent replications.

## Error mechanisms visible in the responses

Several errors survive a status-only assessment. On the vent model's gain-two state, the three raw arms returned `supported`, while their explanations calculated a value above the limit and described the claim as unsupported. The correct submitted-model calculation is `1 + 2 × 5 = 11 > 8`. On the partial HL-5 inspection, the JSON arm returned supported despite J4 being absent; raw EAL and the instruction arm produced extra claim keys and included a supported joint claim. The strict parser rightly rejects those extra-key outputs, while the diagnostic named-claim check exposes their false support.

The checked packet also did not guarantee faithful explanations. On the AH-74 record submitted for an AH-73 question, it gave the correct unsupported status but attributed it to a fixture-alignment notice. The decisive rule is the mismatched unit; the packet supplied a status and claim text without a detailed causal trace. On two HL-5 states it contradicted the authoritative supported status. These observations support keeping the host result authoritative and treating recipient text as advisory.

The raw EAL and JSON arms also supported the limited dosing claim during the active C-88 drift challenge. The instruction arm returned a string rather than the required named `claims` map on that state. A model's explanation can sound decisive while missing an objection, inventing a source, using an incorrect arithmetic expression, or contradicting its own status field. This qualitative inspection was conducted after viewing the arms and is an error taxonomy, not a blinded explanation-quality score.

## Inference and next experiment

The measured outcome establishes that the pinned host executed the fixtures and that recipient output fidelity differed on this small, synthetic schedule. The JSON representation was generated from EAL's AST and lacked an independently implemented equal checker. No human developer authored the source in this block; no second masked source-fidelity review was done. The result cannot establish EAL-specific superiority, general model capability, a modest population effect, or cost savings under an optimised direct baseline. The existing deployment protocol requires independent briefs, equal-capability checker execution, source review, and cross-developer reuse. A follow-up packet arm should provide concise checked reasons and objection paths, then score explanations blind to arm while retaining the host's status as the application output.
