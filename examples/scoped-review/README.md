# Scoped review example

This synthetic case exercises modules, context inheritance into three evidence declarations, pure expressions, decreasing evidence-list recursion, nested block arguments, generated-route objections, reviewed rank/partial priorities and preferred sceptical acceptance. No observations of a deployed service or model-performance benefits are asserted.

From the repository root after installation:

```sh
python examples/scoped-review/run.py --export-view /tmp/scoped-review.json
```

Import that `aspic-view/3` JSON into the companion visualisation. `release.checks.item` is undercut; the second generated route survives. Its original evidence identity is retained. `release.assess.child` and its parent form nested derivations through claims, and the preference directive remains inspectable as supplied review metadata. The same source uses normal CLI/MCP validate, format, collect, reason, compile and export operations.

The [composition specification](../../docs/eal3-composition.md) records binding, termination, import, quantity and scope-transfer rules. Separate scope-transfer and solver tests cover typed transport metadata, partial-order incomparability, cyclic theory construction and empty stable-extension families.
