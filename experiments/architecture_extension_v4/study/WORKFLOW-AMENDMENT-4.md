repository `OPENAI_API_KEY` secret. The account subsequently returned
"You have no credits remaining" during assigned sessions. This produced
partial, arm- and order-dependent acquisition. Preserve the 0.1.3 freeze,
assignment ledger, successful and failed invocations, uninvoked sessions,
usage traces and analysis as a separate incomplete intention-to-treat cohort.

failed 0.1.3 assignments with later successes or present a complete-case

`CODEX_API_KEY` from `secrets.OPENAI_API_KEY` to `secrets.CODEX_API_KEY`. The
runner's process variable was already named `CODEX_API_KEY`; this amendment
changes the credential source and potentially the billing account. Record
credential availability, model identity, actual billing channel and usage
without exposing the key. One Responses API request for `gpt-6-sol`, with a
64-token output cap and `store: false`, runs inside the same outer mount and
proxy route before nine parallel blocks start. A 2xx response with usage
proves immediate model entitlement, not sufficient balance for the full wave
or authenticated Codex CLI operation. Only an allowlisted status, token counts,
and elapsed time leave the runner; no provider response or error trace is
uploaded. This check's usage is operations data, not a study episode or a
verified provider bill.

This is a new full cohort starting all B–C–D lineages from the same frozen A
fixtures, followed by fresh paired decision sessions. It does not continue a
0.1.3 candidate or reuse any agent context. A new 256-bit seed is committed
once in the 0.1.4 manifest. Within each system, select one of the two cyclic
orientation sets and shuffle its three rotations across blocks. Each arm
then appears once in each execution position for that system. The previous
allocation put P1 first in seven of nine blocks, which made credit exhaustion
strongly aligned with arm. The restricted allocation has 12 possible
schedules per system. Randomisation inference, if used, must enumerate
those schedules rather than permuting triads independently.

The three systems, B/C/D briefs, hidden assessor, critical check IDs,
source-derived packet semantics and P1/P2 parity, decision case oracles,
