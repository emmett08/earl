# Feature B: partial returns

After an order has been fulfilled, a customer may return a subset of the units on its shipments. Add `CheckoutService.return_items(order_request_id, return_request_id, lines)` where `lines` is a tuple of `ReturnLine(shipment_id, sku, quantity)` records. Return a `ReturnReceipt(return_request_id, refunded_amount, lines)` for accepted positive quantities. For each accepted unit, refund its original quoted unit price plus unit tax and restore one unit to the warehouse that shipped it. The original order and shipment history must remain available; record the cumulative returned quantities so later returns cannot exceed shipped quantities.

For example, an order shipped two units of one SKU from `north` and one from `south` at £10 plus £2 tax per unit. Returning one `north` unit and the `south` unit refunds £24, adds one unit to each respective warehouse and leaves one `north` unit eligible for a later return. A return may combine lines from different shipments. Reject unknown orders or shipments, non-positive quantities, SKU mismatches and cumulative over-returns without refund, stock change or return event.

The same return request ID with the same content returns the original receipt without repeating refund, stock restoration or event publication. Reusing it with different content is an error. If refund fails, no stock or recorded return may change. If a subsequent step fails, retries must not issue another refund. Record an event for each accepted return with the request ID, affected shipment allocations and refunded amount; transient event publication failures remain retryable without repeating the return. Preserve checkout and event-retry behaviour from feature A.
