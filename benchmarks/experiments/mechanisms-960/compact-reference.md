# EAL/2 interpretation reference for this finite study

The requested status concerns the named claim, declared context and assessment time. A claim is `supported` if a usable argument is accepted with every required evidence item, assumption, premise claim and method condition satisfied and no accepted objection blocks it. An independent alternative argument can survive a challenge to another route. A source-usable route affected by an accepted or undecided attack is `contested`. If no route has usable sources, the claim is `unsupported`; this does not establish its negation. If the requested environment differs from the declared claim environment, the status is `out_of_scope`.

An observation supplies evidence only when its declared tool, version, input request, source, context, original observation time, digest and value predicates are eligible. A stale or different-scope record is not repaired by a plausible numerical value. A signed or matching digest binds bytes to an asserted acquisition; it does not prove a physical reading. A proposal is never evidence. A computed status is informative only if its assessment identity and admitted record set match the current source, claim, context, time and method registry. A bare earlier or forged verdict is not a fresh assessment.

For a typed proposition, check subject, quantity, units, scope, interval, exact formal query, bound evidence and result predicate. The method computes over the admitted payload; the text of the claim supplies an author's interpretation, not a mathematical proof. A complete sampled trace requires the declared endpoints and maximum gap. `holds: false` on a complete trace can support an explicitly negative claim; incomplete coverage cannot establish non-detection, although a documented in-scope violating sample can support a bounded violation under its method contract. A numerical result with a different origin or formal query does not answer the specified proposition.

Arguments use all listed sources conjunctively, and alternative arguments for a claim are disjunctive. Objections can target claims, arguments, reasoning steps, assumptions or other objections. An accepted independent defence can defeat an objection; a defence depending solely on the claim it attempts to restore cannot bootstrap itself. The finite support/attack evaluator starts undecided and computes the least justified labelling. Source usability and accepted attack structure determine the final engineering status. Method output, eligibility and full argument status are different stages; an intermediate memo about one stage does not itself state the later conclusion.

Return exactly one JSON object with `claims`, mapping the requested claim identifier to one of `supported`, `contested`, `unsupported`, `out_of_scope`, and `basis`, a list of short reason strings. Use only supplied information; if raw records are absent, an earlier proposed answer cannot supply them. No live tool is available to you in this study.
