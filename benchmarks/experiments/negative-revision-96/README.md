# 96-call finite negative-revision pilot, developmental amendment A1

This is a new, versioned executable schedule inspired by the **specified but
unexecuted** `INV-EAL-NEGATIVE-REVISION-001/0.1.0`. It does not claim that the
original protocol was executed unchanged. The exact original bytes from the
merged PR must remain historical; this study declares
`0.2.0-dependent-family-developmental` in `plan.json`.

Eight selected synthetic engineering briefs use a common sampled-negative
method and generated EAL/JSON scaffolds, with distinct objection targets,
surviving positive route, adverse-route ineligibility, independently asserted
defence, a positive route requiring qualified absence, inclusive bound and
state substitution. Per-root ancestry is recorded in `specifications.json`.
The eight roots are **not independently authored**: one author selected the
briefs and generated both representations. Reviewer comments can check the
rules but cannot turn this into eight independent external engineering tasks.
The synthetic records are author assertions and do not authenticate devices.

The primary finite outcomes are whole three-state sequences and false support.
The unit for descriptive contrasts is the root. **Stage A** assigns 48 fresh
one-shot requests: 8 roots × 3 states × EAL/JSON view. Each of the 24 states
also has two deterministic canonical checker executions, for 48 local checks.
**Stage B** has 16 independent format threads: 8 roots × EAL/JSON × three
linked draft/revision calls, another 48 model calls. A turn's exact prompt is
hashed and recorded immediately before transmission, since it incorporates
the preceding raw response and diagnostic feedback. Stage B finite-suite
replay is a code-defined functional test; independent brief-to-source human
fidelity review remains unavailable. Both checker endpoints are independently
implemented and use the same selected formal method contract. A correct host
status is conditional on the author's warrant and acquisition assertions.

Canonical preflight requires exact EAL/reference/generic status parity on all
24 authored states. Per root it also mutates forged version, wrong context,
stale/future/missing trace, short typed-input interval, wrong formal query,
weak detector, incomplete coverage, and where applicable wrong independent
audit finding and missing synthetic supersession assertion. The conveyor's
third state explicitly asserts a *synthetic* withdrawal and later replacement
at 08:25 UTC, with a digest of its 08:20 adverse predecessor. The host checks
that assertion but cannot authenticate the author or show the first reading
was false. Neither a successful partial counterexample nor a complete sampled
non-detection establishes behaviour between sampled times.

The model receives briefs, formal text and synthetic records without the
reference labels. Its Stage B feedback contains only the current candidate's
computed statuses and bounded diagnostics. Candidate sources are replayed
against all three states separately, including future states not revealed as
feedback. All attempted malformed, refused and failed outputs remain in the
denominator; there are no automatic retries. The runner marks a call pending
on durable storage before transmission and refuses silent resume after a
pending/failed call.

## Reproduce and run

```sh
python benchmarks/experiments/negative-revision-96/build_fixtures.py
PYTHONPATH=src:. python benchmarks/experiments/negative-revision-96/run.py /tmp/negative96-fresh --freeze-only
OPENAI_API_TOKEN='supplied externally' PYTHONPATH=src:. python benchmarks/experiments/negative-revision-96/run.py /tmp/negative96-fresh --resume
PYTHONPATH=src:. python benchmarks/experiments/negative-revision-96/analyse.py /tmp/negative96-fresh --output /tmp/negative96-fresh/analysis.json
```

The placeholder credential above is explanatory and should be supplied
through the environment, never a command literal retained in shell history.
`run.py` accepts `OPENAI_API_TOKEN` and passes it to the configured provider's
`OPENAI_API_KEY` environment name in process memory. The pinned snapshot is
`gpt-4.1-nano-2025-04-14`; a returned identity change stops the campaign.
At verified OpenAI model-page rates of $0.10/$0.025/$0.40 per million
input/cached input/output tokens, 96 calls
of at most 50,000 UTF-8 prompt bytes and 3,000 output tokens have a conservative
reservation below $0.596, under the $1.20 configured-rate campaign cap. Actual
usage and price estimates are recorded per attempted call; the provider bill
is authoritative. Anticipated wall time is roughly 15–30 minutes under the
observed nano latency but is not guaranteed. Human source review, acquisition
and deployed answer-review labour are unmeasured, so all-in cost per accepted
decision is unavailable.

The runner and results support only a selected-family developmental feasibility
description. A confirmatory 96-call claim requires new independently authored
and masked human-adjudicated roots plus a separate freeze; the original
version remains unrun.
